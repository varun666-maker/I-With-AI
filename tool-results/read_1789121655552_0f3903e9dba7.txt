    46→## Screen 2: Auth Page `/auth`
    47→
    48→**What is this?**
    49→The registration AND login page. Everything happens on one screen — no navigating between separate pages for sign up vs login vs OTP vs profile setup. Instead, the content switches in-place.
    50→
    51→**What does the user see?**
    52→
    53→On desktop, the screen is split in half. The left side has a gradient background with the platform tagline and a small 3D avatar. The right side has the form. On mobile, only the form shows (full screen).
    54→
    55→At the top of the form, there are two tabs: "Sign Up" and "Login". Clicking between them switches the content below.
    56→
    57→### Sign Up Flow (3 steps, all on same screen):
    58→
    59→**Step 1 — Create Account:**
    60→The user sees 3 input fields: Name, Email, Password (with hint "Min 8 characters"). Below that, a horizontal line with "OR" in the middle, then a "Continue with Google" button. At the bottom, a big "Create Account" button.
    61→
    62→The user fills in their details and clicks Create Account. The button shows a spinner. The backend sends an OTP to their email.
    63→
    64→**Step 2 — OTP Verification:**
    65→The form content changes. Now the user sees: "We sent a 6-digit code to your@email.com". Below that, 6 individual small input boxes, each accepting one digit. When you type a digit, focus automatically jumps to the next box. When you press backspace on an empty box, focus goes to the previous one.
    66→
    67→Below the boxes, a countdown timer shows "Resend in 4:32". When it reaches 0, it becomes a "Resend OTP" button. There's a "Verify" button at the bottom (disabled until all 6 digits are filled).
    68→
    69→If the user enters the wrong code, a red error message appears: "Invalid code. 2 attempts remaining." After 3 wrong attempts, they must request a new OTP.
    70→
    71→**Step 3 — Profile Setup:**
    72→After OTP is verified, the form content changes again. Now the user fills out their profile:
    73→- Job Role: a dropdown with options like Frontend Developer, Backend Developer, etc.
    74→- Skills: a tag input where they type and get autocomplete suggestions. Clicking a suggestion adds it as a pill/tag. They can remove tags by clicking the × on each pill.
    75→- Education: a repeatable group — each row has Degree (dropdown), Institution (text), Year (text). There's an "+ Add" button to add more rows and a "×" button on each row to remove it.
    76→- LinkedIn URL: optional text input
    77→- GitHub URL: optional text input
    78→- "Complete Setup" button at the bottom
    79→
    80→After clicking Complete Setup, the account is created with role = "student", and the user is redirected to `/dashboard`.
    81→
    82→### Login Tab:
    83→If the user clicks the "Login" tab instead, they see: Email input, Password input, a "Forgot Password?" link, an "OR" divider, "Continue with Google" button, and a "Login" button.
    84→
    85→**Forgot Password flow:** Clicking "Forgot Password?" reveals an email input and "Send Reset Link" button inline. The user enters their email, clicks Send, and sees "Reset link sent to your email." They click the link in their email, which takes them to a page where they set a new password, then come back to login.

    89→## Screen 3: Student Dashboard `/dashboard`
    90→
    91→**What is this?**
    92→The student's home base after logging in. Every time they finish an activity, they come back here. It shows a summary of everything at a glance.
    93→
    94→**What does the user see?**
    95→
    96→At the top: "Welcome back, Priya! 👋" with their name. On the right side, a "Download Report" button. This button is HIDDEN by default. It only appears (with a fade-in + pulse animation) when a WebSocket message arrives saying "REPORT_READY" — which happens about 60 seconds after an interview ends.
    97→
    98→**Top section (2 columns on desktop, stacked on mobile):**
    99→
   100→Left — Score Gauge: A big circular progress ring showing the overall interview score from the last session (e.g., 78%). Below it, "Last: Jan 15" showing when the last interview was.
   101→
   102→Right — Score Trend Line: A line chart showing the scores of the last 10 interview sessions plotted over time. So the student can see if they're improving.
   103→
   104→**Middle section (3 columns desktop, stacked mobile):**
   105→
   106→Column 1 — Skill Radar Chart: A 6-axis radar chart showing scores across 6 dimensions: Technical, Communication, Behavioral, Body Language, Confidence, Problem Solving. The shape of the radar shows where they're strong and where they're weak.
   107→
   108→Column 2 — Resume Score Card: Shows "Resume ATS Score" as a big number (e.g., 87) with a progress bar below it. A "View Full Analysis →" link goes to `/resume`.
   109→
   110→Column 3 — Aptitude Quick Stats: 5 small horizontal bars showing scores per category: Quant, Logical, Verbal, Analytical, DI. Each bar has a label, a filled portion, and a percentage. A "Take Test →" link goes to `/aptitude`.
   111→
   112→**Bottom section (2 columns desktop, stacked mobile):**
   113→
   114→Left — Recent Interviews: A list of the last 5 interviews, each as a small card showing: date, interview type badge (HR, Technical, etc.), score, and a "Replay →" link. If the student has never done an interview, an empty state shows: "Complete your first interview!" with an icon.
   115→
   116→Right — Two things stacked:
   117→1. Learning Roadmap: A checklist showing 6 weeks. Each week has a status icon: ✅ Complete, 🔄 In Progress, or 🔒 Locked. The week theme is shown next to each.
   118→2. Coding Heatmap: A GitHub-style grid of small colored squares showing coding activity over the last 12 weeks. Green squares = days with activity.
   119→
   120→**Very bottom — Fair Usage Summary:**
   121→A small collapsible section labeled "Your self-awareness stats". When expanded, it shows: "Tab switches last test: 3 | Fullscreen exits: 1". There's an info icon with a tooltip that says "These are logged for your awareness only. No penalties." This is important — in Prep Mode, proctoring data is purely informational. It never blocks the user or affects their score.

   125→## Screen 4: Resume Hub `/resume`
   126→
   127→**What is this?**
   128→Where the student uploads their resume and gets a detailed AI analysis back.
   129→
   130→**What does the user see?**
   131→
   132→The page has 3 sub-screens that switch in-place based on what's happening:
   133→
   134→### Sub-screen 4a — Upload:
   135→A centered drag-and-drop zone (about 300px tall) where the user can drag a PDF or DOCX file, or click to browse. Max file size is 5MB.
   136→
   137→After the user selects a file, the filename and size appear below the dropzone, with an "Analyze Resume" button.
   138→
   139→When they click the button, the file uploads. While waiting for the AI analysis (takes about 10-15 seconds), a shimmer skeleton placeholder appears — it has the same shape and layout as the results card, but everything is a pulsing gray animation, so the user knows something is loading and where it will appear.

   147→- Job Fit: 78% with progress bar and a label showing "Backend Developer"
   148→
   149→**Skills section (2 columns):**
   150→- Left: "Skills Found" — tags in green showing Python, FastAPI, React, SQL

   153→**Issues section (2 columns):**

   155→- Right: "Formatting Issues" — a simple bulleted list like "No consistent date format", "Missing LinkedIn URL"

   157→**AI Summary:** A card with 2 paragraphs of narrative text like "Priya has a strong foundation in backend development with Python and FastAPI..."

   160→

   162→
   163→### Sub-screen 4c — Upload History:
   164→A table (or card list on mobile) showing all past resume uploads with columns: Date, ATS Score, Job Fit %, and a "View" link. Clicking "View" switches to the results sub-screen showing that specific analysis. The user can upload new resumes anytime — all versions are saved.

   168→## Screen 5: Aptitude Portal `/aptitude`
   169→
   170→**What is this?**
   171→Where the student takes timed aptitude tests with 25 MCQ questions across 5 categories.
   172→
   173→**What does the user see?**
   174→
   175→3 sub-screens that switch based on the test phase:
   176→
   177→### Sub-screen 5a — Rules Screen:
   178→A centered card showing the test configuration:
   179→- "25 Questions" with an icon
   180→- "30 Minutes" with a clock icon
   181→- "5 Categories" with a grid icon
   182→- Category breakdown: Quantitative (5), Logical (5), Verbal (5), Analytical (5), Data Interpretation (5)
   183→- "No Negative Marking" with a checkmark
   184→- "Unlimited Retakes" with a refresh icon
   185→- "Start Test" button (big, centered, primary)
   186→
   187→### Sub-screen 5b — Test Screen:
   188→This is the main test-taking interface.
   189→
   190→**Top bar:** A countdown timer on the left (shows minutes:seconds), "Q 12 of 25" in the center showing which question they're on, and a Bookmark button on the right.
   191→
   192→**Left side — Question area:**
   193→A small badge showing the category (e.g., "Quantitative"). Below it, the question text. Then 4 option buttons labeled A, B, C, D. The currently selected option is highlighted with an accent border and background. Below the options, "← Previous" and "Next →" navigation buttons.
   194→
   195→**Right side — Navigation Grid:**
   196→A 5×5 grid of 25 small circles. Each circle represents one question:
   197→- Green circle = answered
   198→- Yellow circle = bookmarked
   199→- Orange ring = current question
   200→- Gray circle = unanswered
   201→The user can click any circle to jump directly to that question.
   202→
   203→Below the grid, a legend explaining the colors.
   204→
   205→**Footer:** On the left, small gray text showing "Tab switches: 2 | Fullscreen exits: 0" — this is informational only, just a counter. On the right, a "Submit Test" button (ghost style, not primary — to prevent accidental clicks).
   206→
   207→**Timer behavior:**
   208→- Normal: black text
   209→- Under 5 minutes: turns red, bold, with a subtle pulse animation
   210→- Under 1 minute: red, bold, larger size
   211→- At 00:00: auto-submits whatever has been answered
   212→
   213→**Option selection:** Clicking an option immediately highlights it. No separate "confirm" step needed. If the user clicks a different option, it switches.
   214→
   215→**Bookmarking:** Clicking the bookmark icon marks the current question with a yellow circle in the navigation grid.
   216→
   217→**Auto-save:** Answers are auto-saved every 30 seconds to localStorage. If the browser crashes, the user can resume from where they left off.
   218→
   219→**Tab switch detection:** Every time the user switches tabs or exits fullscreen, a counter increments. In Prep Mode, this counter is shown but it NEVER pauses the test, NEVER warns the user, and NEVER affects their score. It's purely informational.
   220→
   221→**Submitting:** When the user clicks "Submit Test", a confirmation modal appears: "Are you sure? X questions are unanswered." If all 25 are answered, it still shows a modal but says "All 25 questions answered. Submit?"
   222→
   223→### Sub-screen 5c — Results Screen:
   224→After submitting, the results appear:
   225→
   226→**Top:** A score summary: "18/25 Correct (72%)" with a progress bar.
   227→
   228→**Category Breakdown:** 5 horizontal bars, one per category, showing the score. For example:
   229→- Quantitative: 80% (green bar)
   230→- Logical: 60% (yellow bar)
   231→- Verbal: 100% (green bar)
   232→- Analytical: 80% (green bar)
   233→- Data Interpretation: 40% (red bar)
   234→
   235→**Wrong Answers Section:** For each question the user got wrong, a card shows:
   236→- The question text (truncated if long)
   237→- "Your answer: B" in red with an ✕ icon
   238→- "Correct answer: C" in green with a ✓ icon
   239→- An explanation of why the correct answer is right
   240→
   241→**Action:** "Take Again" button at the bottom. This goes back to the Rules screen with a fresh set of 25 random questions from the public bank. Retakes are unlimited.

   245→## Screen 6: Coding Arena `/coding`
   246→
   247→**What is this?**
   248→A coding practice environment with a VS Code-like editor, code execution, and AI code review.
   249→
   250→**What does the user see?**
   251→
   252→On desktop, the screen is split into two panes side-by-side (50/50), with a draggable divider between them. On mobile, the two panes stack vertically — problem on top (collapsible), editor on bottom.
   253→
   254→### Left Pane — Problem Statement:
   255→Shows the coding problem with:
   256→- Title (e.g., "# Two Sum") with a difficulty badge (Easy = green, Medium = yellow, Hard = red)
   257→- The full problem description in formatted text
   258→- Example inputs and outputs in code blocks
   259→- Constraints listed
   260→- If it's a SQL problem, there's also a schema diagram and sample data table
   261→
   262→### Right Pane — Code Editor:
   263→- A language dropdown at the top: Python, Java, C++, JavaScript, SQL, Go, TypeScript
   264→- The Monaco editor below it — this is the same editor engine that powers VS Code. It has syntax highlighting, autocomplete, bracket matching, etc. The editor theme automatically matches the user's appearance mode (light/dark/midnight).
   265→- Below the editor, a "Custom Input" text field where the user can type their own test input
   266→- Two buttons: "▶ Run" (ghost style) and "✓ Submit" (primary style)
   267→- Below the buttons, the test cases section
   268→
   269→**Run button:** Executes the user's code against the 3 visible test cases using the Piston API. Results appear below:
   270→- ✅ Case 1: Passed (12ms, 14MB)
   271→- ✅ Case 2: Passed (8ms, 14MB)
   272→- ❌ Case 3: Failed — Expected [0,1] Got [1,0] (15ms, 14MB)
   273→
   274→**Submit button:** Executes the code against ALL 10 test cases (3 visible + 7 hidden). Shows the pass/fail count:
   275→- ✅ Cases 1-3: Passed
   276→- ✅ Cases 4-7: Passed (hidden)
   277→- ❌ Case 8: Failed (hidden)
   278→- ✅ Cases 9-10: Passed (hidden)
   279→- "7/10 passed"
   280→
   281→**After submit — AI Code Review:**
   282→A panel slides down below the test cases showing the AI's review of the code:
   283→- Overall Score: 85/100 with a progress bar
   284→- Time Complexity: O(n) ✅ Optimal
   285→- Space Complexity: O(n)
   286→- Sub-scores: Code Quality 90/100, Readability 85/100, Correctness 70/100
   287→- Strengths: green bullet list ("Clean variable naming", "Handles edge cases")
   288→- Suggestions: yellow bullet list ("Consider using a dictionary for O(1) lookup instead of nested loop")
   289→- "Refactored Snippet" — a collapsible section showing improved code
   290→
   291→**Language switching:** When the user switches the language dropdown, a confirmation modal appears: "Switching language will clear your code. Continue?" This prevents accidental code loss.
   292→
   293→**Auto-save:** Code is auto-saved to localStorage every 30 seconds. A small "Auto-saved ✓" message briefly appears after each save.
   294→
   295→**Proctoring footer:** Same as aptitude — "Tab switches: 1 (logged only)" — informational, never blocks.

   299→## Screen 7: AI Interview `/interview`
   300→
   301→**What is this?**
   302→The flagship feature. The student has a live, real-time conversation with an AI interviewer who asks questions, listens to answers, generates follow-ups, and analyzes body language.
   303→
   304→**What does the user see?**
   305→
   306→4 sub-screens:
   307→
   308→### Sub-screen 7a — Setup:
   309→"Choose Interview Type" heading with 6 cards in a 3×2 grid (2 columns on mobile):
   310→
   311→1. HR/Behavioral — 20-30 min, 8-12 questions
   312→2. Technical — General — 30-45 min, 10-15 questions
   313→3. Technical — Role-Specific — 30-45 min, 10-15 questions
   314→4. Managerial — 25-35 min, 8-10 questions
   315→5. Company-Specific — 25-35 min, 8-12 questions
   316→6. Full End-to-End — 55-75 min, 25-40 questions
   317→
   318→Each card has an icon, title, description, duration, and question count. The user clicks one to select it (it gets highlighted with an accent border).
   319→
   320→Below the cards, a "System Check" section:
   321→- "🎤 Microphone: [Test]" button — clicking it requests mic permission and shows "Working ✅" or "Not detected ❌"
   322→- "📷 Camera: [Test]" button — clicking it requests camera permission and shows a small webcam preview or an error
   323→
   324→"Begin Interview" button (disabled until both mic and camera are confirmed working).
   325→
   326→### Sub-screen 7b — Live Interview:
   327→
   328→**On desktop, split into two sides:**
   329→
   330→**Left side — Avatar and Analysis:**
   331→- A 3D animated avatar (Three.js) that's about 320×320 pixels. The avatar has:
   332→  - Idle animation: gentle breathing/bobbing when waiting
   333→  - Speaking animation: mouth moves (lip-synced) when the AI is asking a question
   334→  - Thinking animation: slight head tilt with a "..." typing dots overlay when the AI is generating the next question
   335→- Below the avatar, voice waveform bars — about 20 vertical bars that animate their height based on the audio volume when the user is speaking
   336→- Below the waveform, real-time analysis indicators:
   337→  - Emotion: 😐 Neutral (updates every 5 seconds via face-api.js running in the browser)
   338→  - Eye Contact: 78% (via MediaPipe running in the browser)
   339→  - Posture: ✅ Good or ⚠️ Check posture (via MediaPipe)
   340→
   341→**Right side — Question and Transcript:**
   342→- "AI Question:" label followed by the current question text in a card
   343→- A microphone toggle button: "🎤 Speak now..." — the user can click to start/stop recording, or just start talking and it auto-detects
   344→- Live Transcript: A chat-like display that builds in real-time as the AI speaks and the user answers:
   345→  - AI messages appear left-aligned in accent color
   346→  - User messages appear right-aligned in a subtle background
   347→  - Each message has a small timestamp
   348→  - The transcript auto-scrolls to the latest message
   349→- When the AI is generating the next question, typing dots appear: "● ● ● AI is thinking..."
   350→
   351→**Top bar:** Countdown timer (red when <5min), "Q 3 of 10" showing progress, and an "End Early" ghost button (confirmation modal: "End interview early? You won't be able to resume.")
   352→
   353→**Footer:** Same proctoring info as other screens — "Tab switches: 1 | Fullscreen exits: 0 (logged only)"
   354→
   355→**On mobile:** Everything stacks vertically — avatar on top (smaller, 200px), question and transcript below.
   356→
   357→**What happens technically during the live interview:**
   358→1. The AI avatar speaks the first question using Web Speech API text-to-speech. The avatar's mouth moves in sync.
   359→2. When the avatar finishes speaking, the microphone activates and the user speaks their answer.
   360→3. The audio is recorded and sent to the server, where Whisper converts it to text. The transcript appears live.
   361→4. The transcript is sent to Gemini, which generates a dynamic follow-up question based on the user's answer. The avatar speaks this new question.
   362→5. This loops: Question → User Answer → Follow-up → User Answer → ... until all questions are done.
   363→6. Simultaneously, face-api.js detects the user's emotion every 5 seconds (runs in browser, free). MediaPipe tracks eye contact percentage, posture, and hand gestures (runs in browser, free). These update the indicators on the left side.
   364→7. The entire session is recorded via MediaRecorder (video + audio) and uploaded to Cloudinary after the interview ends.
   365→
   366→### Sub-screen 7c — Processing:
   367→After the interview ends, this screen shows:
   368→
   369→A large conic spinner (the rainbow spinner animation). Below it, a list of processing steps that update one by one via WebSocket:
   370→- ✅ Transcribing audio...
   371→- ✅ Evaluating answers...
   372→- 🔄 Generating report... (currently in progress)
   373→- ⬜ Calculating scores...
   374→
   375→Below: "This takes approximately 60 seconds"
   376→
   377→If it's been more than 5 minutes: "Taking longer than expected. We'll notify you when ready." with an option to go to the dashboard and wait there.
   378→
   379→The actual processing happens as a Celery background job on the server. The frontend just shows progress via WebSocket.
   380→
   381→### Sub-screen 7d — Done:
   382→A centered card with:
   383→- Large ✅ icon with a spring scale-in animation
   384→- "Interview Complete!"
   385→- "Your report is being generated and will appear on your dashboard."
   386→- "Go to Dashboard" button
   387→
   388→About 60 seconds later, a WebSocket message "REPORT_READY" arrives, and the "Download Report" button on the dashboard activates.

   392→## Screen 8: Report `/report/:id`
   393→
   394→**What is this?**
   395→A full, detailed PDF report viewable in the browser. It has 17 sections covering every aspect of the interview performance.
   396→
   397→**What does the user see?**
   398→
   399→A long scrollable page with 17 sections, each in its own card with a section number and title. A sticky "📥 Download PDF" button stays visible in the top-right corner while scrolling.
   400→
   401→The 17 sections are:
   402→
   403→1. **Cover Page** — Platform logo, "Interview Report", candidate name, date, interview type
   404→2. **Executive Summary** — 3 paragraphs giving a high-level overview of how the candidate performed
   405→3. **Overall Score Table** — A table with 6 rows, one per dimension (Technical, Communication, Behavioral, Body Language, Confidence, Problem Solving). Each row shows the dimension name, score out of 100, and a progress bar.
   406→4. **Hiring Recommendation** — A large, prominent badge: "Strongly Recommend" (green), "Recommend" (blue), "Conditionally Recommend" (yellow), or "Not Recommended" (red)
   407→5. **Resume Analysis** — ATS score, job fit percentage, skills found and missing
   408→6. **Aptitude Analysis** — Per-category scores, strengths, and weaknesses
   409→7. **Coding Analysis** — Problems attempted, pass rate, code quality score, AI review summary
   410→8. **Technical Analysis** — Per-question technical accuracy scores and depth ratings
   411→9. **HR/Behavioral Analysis** — STAR method usage evaluation, motivation clarity, culture fit indicators
   412→10. **Communication Analysis** — Clarity score, structure rating, filler word count, pacing analysis
   413→11. **CV/Emotion Analysis** — Dominant emotions detected, average eye contact percentage, posture consistency
   414→12. **Emotion Timeline Chart** — A line chart where X-axis is question number and Y-axis shows emotion scores over time, so you can see how emotions changed throughout the interview
   415→13. **Session Highlights** — 3-5 key moment cards with timestamps, like "Best answer at Q5", "Weakest moment at Q8", "Surprising insight at Q3"
   416→14. **Top 7 Strengths** — A bulleted list with green checkmarks, like "Strong conceptual understanding of distributed systems", "Excellent eye contact throughout"
   417→15. **Top 7 Improvements** — A bulleted list with yellow warning icons, like "Reduce filler words (used 'um' 23 times)", "Provide more structured answers using STAR method"
   418→16. **6-Week Learning Roadmap** — 6 collapsible cards, one per week. Each shows: week theme (e.g., "Week 1: Core Fundamentals"), daily goal, free resource links, and a milestone to achieve
   419→17. **Final Recommendation** — A closing paragraph with actionable next steps

   423→## Screen 9: Interview Replay `/replay/:id`
   424→
   425→**What is this?**
   426→A way to re-watch a past interview with the video recording synced to the transcript and AI annotations.
   427→
   428→**What does the user see?**
   429→
   430→**Top:** A video player with standard controls (play/pause, seek, volume) and a current time display (e.g., "12:45 / 25:30"). The user can click anywhere on the progress bar to jump to that timestamp.
   431→
