Chapter 01

Platform Overview & Tech Stack

InterviewAI is a dual-mode AI SaaS platform that simulates an end-to-end corporate hiring pipeline. Built on a single codebase, it serves two completely separate user experiences: a self-directed Prep Mode for students and job seekers who want to practice interviewing with an AI, and a Hiring Mode for companies that want to actually screen and hire real candidates at scale. The two modes share the same AI backend (Gemini 1.5 Flash, Whisper, MediaPipe, face-api.js), the same database primitives, and the same component library, but they differ fundamentally in their proctoring philosophy: Prep Mode treats proctoring signals as informational only — a self-awareness tool — while Hiring Mode treats them as enforced rules with auto-submission, integrity flags, and 20% score penalties.
User Roles
Four Roles, Four Permission Surfaces
The platform models four distinct roles, each scoped to a different slice of the data. A single email can only hold one role at a time — a user cannot be both a student and a candidate, because the two experiences have different data privacy implications (students own their data; candidates' data is shared with the hiring company).
Role Created via Sees Write scope
student Self-registration on /auth Own profile, own interviews, own reports Own data only · unlimited retakes
candidate Admin shortlist → invite email One campaign only · own round scores Test answers · interview answers · zero retakes
company_admin Self-registration on /company/register Own company · own campaigns · all candidates in those campaigns CRUD campaigns · questions · shortlist · final decisions
super_admin Script-created at deployment Everything across all companies Suspend companies · GDPR delete · reseed questions · system config
Tech Stack
Frontend · Backend · AI · Infrastructure
The stack was chosen for three reasons: (1) every layer is free or has a generous free tier, (2) each component is best-in-class for its specific job, and (3) the AI layer runs primarily in the browser for face/emotion analysis to keep server costs low. The backend is intentionally polyglot — Postgres for transactional records, Mongo for nested document data (interview reports, proctoring event logs), and Redis for rate limiting and BullMQ job queues.
Frontend
  • React 18 + Vite — SPA with state-based routing (no Next.js for the student app)
  • Tailwind CSS + shadcn/ui + Radix UI — design system primitives
  • Zustand — lightweight global state (auth, current screen, theme)
  • Framer Motion — entrance animations, page transitions, magnetic hover
  • Recharts — radar, line, bar charts for the dashboard
  • Monaco Editor — VS Code-grade editor inside Coding Arena
  • Three.js — 3D animated AI interviewer avatar with lip-sync
  • face-api.js + MediaPipe — browser-side emotion & posture detection
Backend
  • FastAPI (Python 3.11) — async REST API + WebSocket for live interview state
  • PostgreSQL via Supabase — users, companies, campaigns, applicant_pool
  • MongoDB Atlas — aptitude_questions (1,770), coding_problems (315), interview_reports (17-section nested docs), proctoring_events
  • Redis via Upstash — rate limiting, session cache, BullMQ job queue
  • Celery workers — async resume analysis, interview processing (60s), report generation, GDPR deletion
  • Resend — transactional email (OTP, invite emails, password reset)
  • Cloudinary — resume PDFs, interview recordings (video+audio), flagged proctoring webcam frames
  • Piston API — code execution across Python/Java/C++/JS/SQL/Go/TypeScript
AI Layer
  • Gemini 1.5 Flash — primary LLM for resume analysis, interview Q&A, code review, report generation
  • OpenAI Whisper (via API) — speech-to-text for live interview transcripts
  • Web Speech API — text-to-speech for the AI avatar (browser-native, free)
  • MediaPipe — eye contact %, posture, hand gestures (runs in browser, free)
  • face-api.js — emotion detection every 5 seconds (runs in browser, free)
  • COCO-SSD — object detection for phone/extra-person in proctored tests
  • MediaRecorder API — records the interview (video + audio) for later replay
⚡ Rate-Limit Strategy
Gemini has a 15 RPM (requests-per-minute) free-tier limit. The backend enforces a 4-second sleep between consecutive Gemini calls via a Celery semaphore. The Super Admin → AI Usage Monitor screen surfaces rate-limit events in real time so the team can spot abusive users before they hit the daily quota (15,000 requests/day).
Chapter 02

Prep Mode Flow (Student)

Prep Mode is the self-directed practice experience. Any visitor can register, upload their resume, take unlimited aptitude tests, code in the arena, and run live AI interviews — all for free, all without any proctoring penalty. The proctoring signals (tab switches, fullscreen exits, posture flags) are still captured and shown to the student, but framed as self-awareness data rather than enforcement. This is the funnel that converts anonymous visitors into engaged users who eventually tell their friends.

✓ Key Principle: Unlimited Retakes, Informational Proctoring
In Prep Mode, every assessment (aptitude, coding, interview) can be retaken unlimited times. Tab switches and fullscreen exits are logged and shown to the student as a self-awareness stat — they never block, warn, or affect the score. The student is the only audience for their own proctoring data.

Screen 02
Auth Page /auth
Registration AND login on a single screen — no navigating between separate pages for signup vs login vs OTP vs profile setup. The content switches in-place via a step counter. On desktop, the screen is split 50/50: left = gradient + 3D avatar + tagline, right = form. On mobile, only the form shows.
Sign Up Flow — 3 Steps, Same Screen
Step counter persists in top-right of the form card
  • Step 1 — Create Account: Name, Email, Password (min 8 chars). "OR" divider. "Continue with Google" button. "Create Account" CTA → backend sends OTP to email
  • Step 2 — OTP Verification: "We sent a 6-digit code to your@email.com". 6 individual input boxes (auto-advance on type, backspace jumps to previous). Countdown "Resend in 4:32" → becomes "Resend OTP" button at 0. "Verify" button disabled until 6 digits filled. Wrong code → red error "Invalid code. 2 attempts remaining." After 3 wrong attempts → must request new OTP
  • Step 3 — Profile Setup: Job Role dropdown (Frontend/Backend/Full-stack/Data/DevOps/...), Skills tag input with autocomplete, Education repeatable group (Degree + Institution + Year + Add/Remove), LinkedIn URL (optional), GitHub URL (optional). "Complete Setup" → account created with role=student → redirect to /dashboard
Login Tab
  • Email + Password + "Forgot Password?" link
  • "OR" divider + "Continue with Google" button

Forgot Password Flow
Inline expansion — clicking "Forgot Password?" reveals an email input + "Send Reset Link" button. User enters email → sees "Reset link sent to your email." Email contains a tokenized link → user sets a new password → redirected back to login. No separate page route required.
Screen 03
Student Dashboard /dashboard
The student's home base after login. Every time they finish an activity, they return here. The dashboard summarizes everything at a glance: latest score, score trend, skill radar, resume ATS, aptitude breakdown, recent interviews, learning roadmap, coding heatmap, and fair-usage stats.
  • Header: "Welcome back, Priya! 👋" + "Download Report" button (hidden by default — fades in with pulse animation when WebSocket delivers REPORT_READY ~60s after interview ends)
  • Top row (2-col): Left = circular Score Gauge showing last interview % + "Last: Jan 15". Right = Score Trend Line chart (last 10 sessions)
  • Middle row (3-col): Skill Radar Chart (6 axes: Technical, Communication, Behavioral, Body Language, Confidence, Problem Solving) · Resume Score Card (ATS 87/100 + progress bar) · Aptitude Quick Stats (5 horizontal bars: Quant, Logical, Verbal, Analytical, DI)
  • Bottom row (2-col): Left = Recent Interviews list (date, type badge, score, Replay → link). Right = Learning Roadmap checklist (6 weeks: ✅/🔄/🔒) + Coding Heatmap (GitHub-style 12-week grid, green = activity)
  • Fair Usage Summary (collapsible): "Your self-awareness stats" → "Tab switches last test: 3 | Fullscreen exits: 1" + info tooltip "Logged for your awareness only. No penalties."
Screen 04
Resume Hub /resume
Where the student uploads their resume and gets back a detailed AI analysis. The page has 3 sub-screens that switch in-place based on the current state: upload → loading → results → history.
Sub-screen 4a — Upload
  • Centered drag-and-drop zone (~300px tall), accepts PDF/DOCX, max 5MB
  • File selected → filename + size shown below + "Analyze Resume" button
  • Click Analyze → file uploads → 10-15 second AI analysis → shimmer skeleton placeholder (same shape as results card, pulsing gray) appears while waiting
Sub-screen 4b — Results
  • 3 stat cards: ATS Score (87/100, circular gauge) · Overall Resume Score (82/100, progress bar) · Job Fit (78%, progress bar + "Backend Developer" label)
  • Skills (2-col): "Skills Found" tags in green (Python, FastAPI, React, SQL) | "Missing Skills" in red (Docker, CI/CD, Testing) + "Recommended" in yellow (System Design, Redis)
  • Issues (2-col): Grammar Issues list (line #, issue, suggested fix) | Formatting Issues bullets ("No consistent date format", "Missing LinkedIn URL")
  • AI Summary card: 2 paragraphs of narrative ("Priya has a strong foundation in backend development…")
  • Badges: Experience Level: Junior · Word Count: 487 · Pages: 1
  • Actions: "Download Full Report" + "Upload New Resume"
Sub-screen 4c — Upload History
  • Table (or card list on mobile) of all past uploads: Date, ATS Score, Job Fit %, "View" link
  • Clicking "View" re-renders sub-screen 4b with that historical analysis
  • All versions saved permanently — students can upload new resumes anytime
Screen 05
Aptitude Portal /aptitude
Timed aptitude practice. 25 MCQs across 5 categories (Quant, Logical, Verbal, Analytical, DI) — 5 questions per category — in 30 minutes. Three sub-screens switch based on test phase: rules → test → results.
Sub-screen 5a — Rules
  • Centered card: "25 Questions" + "30 Minutes" + "5 Categories" with icons
  • Category breakdown: Quantitative (5), Logical (5), Verbal (5), Analytical (5), Data Interpretation (5)
  • "No Negative Marking" ✓ + "Unlimited Retakes" ↻
  • "Start Test" CTA (big, centered, primary)
Sub-screen 5b — Test
  • Top bar: Countdown timer (left, turns red & pulses <5min, larger <1min) · "Q 12 of 25" (center) · Bookmark button (right)
  • Left — Question: Category badge → question text → 4 options (A/B/C/D, selected = accent border+bg) → Previous/Next buttons
  • Right — Navigation grid: 5×5 grid of 25 circles. Green = answered, Yellow = bookmarked, Orange ring = current, Gray = unanswered. Click any circle to jump. Legend below.
  • Footer: "Tab switches: 2 | Fullscreen exits: 0" (informational only) · "Submit Test" (ghost style to prevent accidental clicks)
  • Timer behavior: Black → red+bold+pulse <5min → red+bold+larger <1min → auto-submit at 00:00
  • Auto-save: Every 30s to localStorage. Browser crash → resume from where they left off.
  • Submit confirmation: Modal — "Are you sure? X questions are unanswered." or "All 25 questions answered. Submit?"
Sub-screen 5c — Results
  • Score summary: "18/25 Correct (72%)" + progress bar
  • Category breakdown: 5 horizontal bars — Quant 80% (green), Logical 60% (yellow), Verbal 100% (green), Analytical 80% (green), DI 40% (red)
  • Wrong answers section: For each wrong question — question text (truncated) + "Your answer: B" (red ✕) + "Correct answer: C" (green ✓) + explanation paragraph
  • Action: "Take Again" button → back to Rules screen with fresh 25 random questions. Retakes unlimited.
Screen 06
Coding Arena /coding
A VS Code-like coding environment with execution and AI code review. On desktop, the screen is split 50/50 with a draggable divider. On mobile, panes stack vertically (problem on top, collapsible; editor on bottom).
  • Left pane — Problem: Title with difficulty badge (Easy=green, Medium=yellow, Hard=red), formatted description, example I/O in code blocks, constraints. SQL problems add a schema diagram + sample data table.
  • Right pane — Editor: Language dropdown (Python/Java/C++/JS/SQL/Go/TS) → Monaco editor (syntax highlighting, autocomplete, bracket matching, theme matches user's appearance mode) → Custom Input field → ▶Run (ghost) + ✓Submit (primary) buttons → Test cases section
  • Run: Executes against 3 visible test cases via Piston API. Per-case result: ✅ Passed (12ms, 14MB) or ❌ Failed — Expected [0,1] Got [1,0]
  • Submit: Runs all 10 test cases (3 visible + 7 hidden). Shows pass/fail count "7/10 passed"
  • AI Code Review panel (slides down after submit): Overall Score 85/100 (progress bar) · Time Complexity O(n) ✅ Optimal · Space Complexity O(n) · Sub-scores (Code Quality 90, Readability 85, Correctness 70) · Strengths (green bullets) · Suggestions (yellow bullets) · "Refactored Snippet" collapsible
  • Language switching: Confirmation modal — "Switching language will clear your code. Continue?"
  • Auto-save: Every 30s to localStorage. "Auto-saved ✓" briefly shown.
  • Proctoring footer: Same as aptitude — informational only
Screen 07
AI Interview /interview
The flagship feature. The student has a live, real-time conversation with an AI interviewer who asks questions, listens to answers, generates follow-ups, and analyzes body language. Four sub-screens switch based on interview phase.
Sub-screen 7a — Setup
  • "Choose Interview Type" — 6 cards in 3×2 grid (2-col on mobile):
    1. HR/Behavioral — 20-30 min, 8-12 Qs
    2. Technical — General — 30-45 min, 10-15 Qs
    3. Technical — Role-Specific — 30-45 min, 10-15 Qs
    4. Managerial — 25-35 min, 8-10 Qs
    5. Company-Specific — 25-35 min, 8-12 Qs
    6. Full End-to-End — 55-75 min, 25-40 Qs
  • Each card: icon, title, description, duration, question count. Click to select (accent border highlight).
  • System Check: "🎤 Microphone: [Test]" → requests permission → "Working ✅" / "Not detected ❌". "📷 Camera: [Test]" → requests permission → small webcam preview or error.
  • "Begin Interview" button (disabled until both mic + camera confirmed working)
Sub-screen 7b — Live Interview
Desktop: split 50/50. Mobile: stacked.
  • Left side — Avatar & Analysis:
    • 3D avatar (~320×320px) — Idle: gentle breathing/bobbing · Speaking: mouth moves (lip-synced) · Thinking: head tilt + "..." typing dots overlay
    • Voice waveform — ~20 vertical bars animate height based on user's audio volume
    • Real-time analysis indicators:
      • Emotion: 😐 Neutral (updates every 5s via face-api.js)
      • Eye Contact: 78% (via MediaPipe)
      • Posture: ✅ Good or ⚠️ Check posture (via MediaPipe)
  • Right side — Question & Transcript:
    • "AI Question:" label + current question text in a card
    • Microphone toggle: "🎤 Speak now..." — click to start/stop, or auto-detects when user starts talking
    • Live Transcript (chat-like): AI messages left-aligned (accent color) · User messages right-aligned (subtle bg) · Each has timestamp · Auto-scrolls to latest
    • When AI is generating next question: "● ● ● AI is thinking..." typing dots
  • Top bar: Countdown timer (red <5min) · "Q 3 of 10" · "End Early" ghost button (confirmation modal: "End interview early? You won't be able to resume.")
  • Footer: "Tab switches: 1 | Fullscreen exits: 0 (logged only)"
Sub-screen 7c — Processing
  • Large conic rainbow spinner
  • Processing steps update via WebSocket:
    • ✅ Transcribing audio...
    • ✅ Evaluating answers...
    • 🔄 Generating report... (currently in progress)
    • ⬜ Calculating scores...
  • "This takes approximately 60 seconds"
  • If >5 min: "Taking longer than expected. We'll notify you when ready." + option to go to dashboard and wait there
  • Backend: Celery background job. Frontend just shows progress via WebSocket.
Sub-screen 7d — Done
  • Large ✅ icon with spring scale-in animation
  • "Interview Complete!"
  • "Your report is being generated and will appear on your dashboard."
  • "Go to Dashboard" button
  • ~60s later: WebSocket REPORT_READY arrives → "Download Report" button on dashboard activates
🔧 Technical Loop (Live Interview)
1. AI avatar speaks first question via Web Speech API TTS (mouth sync).
2. When avatar stops, mic activates → user speaks answer.
3. Audio recorded + sent to server → Whisper transcribes → transcript appears live.
4. Transcript sent to Gemini → generates dynamic follow-up → avatar speaks new question.
5. Loop: Question → Answer → Follow-up → Answer → ... until all questions done.
6. Simultaneously: face-api.js detects emotion every 5s. MediaPipe tracks eye contact %, posture, gestures. Indicators update on left side.
7. Entire session recorded via MediaRecorder (video+audio) → uploaded to Cloudinary after interview ends.

Screen 09
Interview Replay /replay/:id
Re-watch a past interview with the video recording synced to the transcript and AI annotations. Reached by clicking "Replay →" on any interview card.
  • Video player: Standard controls (play/pause/seek/volume) + current time "12:45 / 25:30". Click anywhere on progress bar to jump.
  • Transcript panel (scrollable): Each Q&A pair listed — AI question + timestamp (e.g. "0:00") + user answer + timestamp (e.g. "0:15") + AI annotation/note ("Good structure, could mention projects"). Click any line → video jumps to that timestamp.
  • Emotion timeline strip: Horizontal strip of emotion icons per question — 😐──😐──😊──😐──🤔──😐

Screen 10
Profile /profile
Where the student edits personal info used by the AI to personalize interview questions. 4 tabs.
  • Tab 1 — Personal Info: Name, Phone, Date of Birth, City, Avatar upload (image file)
  • Tab 2 — Education: Repeatable list — Degree (dropdown) + Institution (text) + Year (text). "+ Add Education" button + "×" remove per row.
  • Tab 3 — Skills: Tag input with autocomplete. Type → see suggestions → click to add. Existing skills appear as removable pills.
  • Tab 4 — Job Preferences: Preferred roles (multi-select) · Experience level (dropdown) · Expected salary (text) · Preferred locations (tag input)
Why profile data matters
Profile data is sent to Gemini when generating interview questions. If the user is a Backend Developer with Python/FastAPI skills, the AI asks backend-specific questions (APIs, DB, queues) instead of generic ones. The more complete the profile, the more targeted the practice.
